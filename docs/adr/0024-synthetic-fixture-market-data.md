# ADR 0024: Synthetic fixture market data for the implementation pass

Status: **Accepted — owner-approved fixture source**; engineering details are choices under OD-01. Date: 2026-09-23.

## Context and history

Data, feature, regime and point-in-time code needs deterministic multi-instrument daily history with realistic defects to test against (AC-09, AC-20). Real sources remain OD-04 and are OPEN, vendor data cannot be committed, and bulk market data stays out of version control. M2 still requires a qualified real source; fabricated data must never be presented as live ingestion. For this implementation pass the owner approved a synthetic fixture market-data source instead of a real vendor.

## Decision

Commit `data/fixtures/market/synthetic-us-equities-v1`, generated by `aura.data.fixture_generator` from seed 20260923. Its provenance class is `SYNTHETIC_FIXTURE`, and the manifest declares the license MIT (repo), no third-party content and `not_market_data: true`.

- **Instruments.** Twelve fictional instruments: ten equities and two ETF-like baskets. Each has a stable `inst_syn_NNNN` ID and a fictional sector. Every symbol starts with `SYN` and contains a digit. US exchange tickers use letters only, so no symbol can collide with a real ticker.
- **Calendar.** 380 sessions on `FIXTURE_WEEKDAY_V1`: weekdays minus declared fixture holidays, each 09:30 to 16:00 America/New_York. Instants are stored in UTC, and the window crosses three daylight-saving changes. This is not an exchange calendar: it has no early closes and no unscheduled closures.
- **Bars.** Unadjusted (`RAW`) daily bars come from a seeded regime-switching random walk with trend, range-bound, high-volatility and drawdown segments. `available_at` is the close plus a declared 15-minute publication delay unless a scenario states otherwise. Instruments, effective-dated symbols, universe ADD/REMOVE events and corporate actions each carry their own `available_at`.
- **Traps.** The manifest declares thirteen traps. Each lists its rows, expected handling and covering test: late revision, provisional-then-final bar, missing session, impossible OHLC, identical and conflicting duplicates, out-of-order delivery, unknown instrument ID, mid-period listing, delisting kept in historical membership, ticker rename, unsupported 2:1 split and stale tail.
- **Determinism.** The generator uses integer SplitMix64 draws, `Decimal` under a pinned context, LF line endings and float-free formatting. `.gitattributes` disables line-ending conversion for `data/fixtures/`. Tests regenerate the dataset and compare SHA-256 hashes with the committed files and the manifest. Any change to the generated bytes needs a new dataset version; v1 is immutable.
- **Format.** Small CSV files with a JSON manifest: reviewable in diffs and free of new dependencies. Parquet/DuckDB (ADR-0004) remains the analytical store for real history.

## Alternatives

Vendor samples or downloaded history would need a rights review and a provider decision (OD-04, OD-10), and they cannot be committed. Tiny hand-written files cannot exercise a 200-session warm-up, regime variation, daylight-saving changes or survivorship. A float-based or NumPy generator would add a dependency, and platform-specific float formatting would break byte-identical output. Generating at test time without committing the result leaves no reviewable immutable artifact and can hide generator drift. Parquet fixtures would need pyarrow and cannot be reviewed as text.

## Consequences and remaining decisions

The dataset is not market data. It cannot support investment claims, strategy qualification (OD-15) or M2 completion, and it neither selects nor qualifies a provider: OD-04 remains OPEN. `FIXTURE_WEEKDAY_V1` does not settle calendar or session policy (OD-03). Corporate-action support remains unimplemented. The split is a declared unsupported event that must make affected features INVALID or exclude the instrument (AC-20). Expected-handling codes describe what correct data-quality code does with each trap; freshness, gap and quality thresholds remain OD-04. Generator segments are test parameters, not regime classifications (OD-17). A symbol period's end becomes known with the row that replaces it, so consumers resolve symbols with `as_of <= knowledge_cutoff`.
